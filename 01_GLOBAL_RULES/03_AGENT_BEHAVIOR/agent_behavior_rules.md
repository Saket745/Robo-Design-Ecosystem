# 🤖 Agent Behavior Rules

## 1. Universal Agent Protocols

All subagents operating in the Antigravity ecosystem must adhere to the following behavioral standards:
*   **Bounded Focus**: An agent must operate only within its specified scope (e.g., `planner_agent` organizes tasks, and must not write code or execute shell scripts).
*   **Context Preservation**: Conversation logs, outputs, and inputs must be structured. Do not dump raw console outputs or verbose stack traces into the central memory vault.
*   **Read-First, Update-Last**: Establish state before taking any action. Never mutate external states directly; all outputs must go through the state manager.

---

## 2. Execution & Run Loop Limits

*   **Recursive Spawning Prohibited**: Agents are strictly forbidden from spawning child subagents recursively or creating nested command execution environments.
*   **Loop Guards**: Long-running or infinite loops (e.g., `while(true)`) are banned. Any iterative action must have a maximum iteration limit (default max: 5 loops) and a configurable timeout.
*   **Terminal Sandboxing**: Terminal commands proposed or executed by agents must run inside sandboxed environments (`14_SANDBOX`) and must not access core system paths or system configurations.

---

## 3. Confidence Thresholds

Every autonomous step or plan proposal generated by an agent must calculate a self-assessed **Confidence Score** between `0.0` and `1.0`.

*   **Confidence >= 0.8**: The agent may proceed automatically with executing sandboxed steps or tasks.
*   **0.5 <= Confidence < 0.8**: The agent must log a warning and request a validation review from the `validation_agent` before execution.
*   **Confidence < 0.5**: The agent must immediately halt, revert local mutations, and escalate to the Master Orchestrator or the User.

---

## 4. Escalation & Intervention Protocols

Immediate escalation to the **User** is triggered under the following conditions:
1.  **Permission Escalations**: Attempts to modify files in the immutable zones (`00_CORE_BRAIN`, `01_GLOBAL_RULES`, `07_SECURITY`).
2.  **Unsandboxed Commands**: Executing network fetches, system configurations, or administrative commands outside the designated sandbox.
3.  **Validation Failures**: Repeating validation failures on the same task sequence (exceeding 3 retries).
4.  **Unknown Errors**: Unhandled framework exceptions or system-level crashes.
5.  **Sensitive Secrets Access**: Requests to read encrypted secrets without authorized credentials.
